# Rerank vs Baseline 对比报告 v1

- 日期：2026-11-24
- 实验目标：只验证 rerank 的增益，不引入 Self-query/生成模型
- 基线：`baseline_retrieval_v1.json`（纯向量检索）
- 实验：`retrieval_report_rerank.json`（纯向量检索 + rerank）
- 机器可读对比：`rerank_comparison_v1.json`
- 评测集：`tests/evaluation/qa_set.jsonl`，57 条可回答问题
- 相关性粒度：页面 URL，去重后计算
- Reranker：`BAAI/bge-reranker-base`
- 召回候选：`candidate_k=30`
- 评测 rerank 输出：top 10（用于计算 1/3/4/5/10 的截断指标）
- 生产默认：`top_n=4`

> 说明：评测时 rerank 保留 top 10，因此 `@1/@3/@4/@5` 与生产 top_n=4/5 的重排顺序一致；`@10` 仅用于观察更高召回。

## 4. 结论与建议

1. **保留 rerank**：top-1 从 42.11% 提升到 52.63%，生产 `k=4` 下 Hit 从 75.44% 提升到 82.46%，MRR 从 56.87% 提升到 66.52%
2. **暂不把 top_n 提到 10**：Hit@10 下降 5.26%，更多上下文不一定有用；生产建议维持 `top_n=4`，最多测试 5
3. **候选池可继续试 50**：当前 `candidate_k=30`，Hit@10 下降可能来自候选覆盖或重排噪声；下一步测试 50 并观察是否能恢复召回
4. **中文和概念题需要更好的 reranker**：可测试 `BAAI/bge-reranker-v2-m3`
5. **下一步应单独评测 Self-query**：当前实验是纯向量 + rerank，未利用 title/url 元数据过滤
6. 不建议把 rerank 和其他改动同时上线；先确认 candidate_k、reranker 模型和 top_n
